# Review Manager UI·반응형 작업

## 작업 전

1. `AGENTS.md`의 프로젝트 개요·디자인 시스템·주요 디렉터리에서 해당 화면의 기존 동작과 컴포넌트 책임을 확인합니다.
2. 루트 `DESIGN.md`와 `src/app/globals.css`의 디자인 토큰을 읽습니다.
3. `src/components/ui`와 기존 도메인 컴포넌트에 재사용할 버튼·카드·입력·표·레이아웃이 있는지 찾습니다.

## 구현 원칙

- 모바일 우선으로 구조를 검토하고, 데스크톱과 모바일에서 기능과 정보의 의미가 달라지지 않게 합니다.
- 고정 폭, 과도한 가로 배치, 불필요한 절대 위치를 피하고 작은 화면에서 주요 조회·저장·이동 동작이 가려지지 않게 합니다.
- 터치 가능한 버튼과 간격을 확보하고, 고정 헤더·하단 메뉴·모바일 안전 영역이 서로 겹치지 않는지 확인합니다.
- hover, 우클릭, 넓은 화면만 가능한 동작을 핵심 기능의 유일한 방법으로 사용하지 않습니다.
- 기존 색상·글꼴·반경·경계선·상태 표현을 재사용하고, 장식만을 위한 UI를 추가하지 않습니다.
- UI 동작이나 화면 구조가 바뀌면 `AGENTS.md`의 해당 프로젝트 개요도 갱신합니다.

## 검증

- 데스크톱과 모바일 브라우저 폭에서 주요 화면을 확인합니다.
- 로딩·빈 상태·오류 상태와 키보드 포커스·`aria-label`이 필요한 동작을 함께 점검합니다.
- 변경 후 `npm run lint`와 관련 테스트를 실행하고, 라우트나 빌드 설정에 영향을 주면 `npm run build`도 실행합니다.
